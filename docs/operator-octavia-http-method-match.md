# HTTPRoute method matching on Amphora

The method profile matches the nine Gateway API v1.7.0 HTTP methods by their exact uppercase value. Within an alternative, the method is combined with the listener hostname, path and configured exact headers. Multiple alternatives can select the same backend. An unmatched request receives HTTP 404. A configured catch-all route can handle it instead, including an `OPTIONS` request with target `*` or a `CONNECT` request in authority form.

1. Apply the Octavia migrations and update the API and Amphora workers to builds that support `HTTP_METHOD` and fixed HTTP responses. Enable `enabled_http_method_match_providers = amphora` and `enabled_gateway_action_providers = amphora` in Octavia's `[api_settings]` section. For matches that use exact headers too, enable `enabled_http_header_exact_providers = amphora`.
2. Read `GET /v2/lbaas/providers/amphora/gateway_capabilities` using the controller's project and regional endpoint. It must advertise `http_method_match_v1` and `fixed_http_responses_v1`. An exact-header match also requires `http_header_exact_v1`.
3. Enable `--octavia-http-method-match` and `--octavia-fixed-http-responses` on the controller. Add `--octavia-http-header-exact` for exact headers. The standalone overlay `config/octavia-http-method-match` and the Magnum overlay `integrations/magnum-capi-helm/workload-octavia-http-method-match` set all three flags. For Magnum, render the overlay as `gateway-controller.yaml` and pin the manifest checksum and controller image in the conductor configuration. [Magnum operator procedure](qualification/v1.7.0/magnum-operator.md)

To combine a redirect with a higher-priority forwarding rule that adds a method match, enable `--octavia-http-request-redirect` in a region advertising `http_request_redirect_v1`. Amphora evaluates the method rule first. Requests that miss it can still receive the redirect. With this option disabled, an overlap that needs ordered evaluation gives the redirect route `Accepted=False` with reason `UnsupportedValue`. [Regional configuration](operator-octavia-http-actions.md#enable-request-derived-redirects)

A temporary discovery failure, including a response with no capability list, keeps the last verified policies serving and pauses changes that would remove their protection. If Octavia explicitly withdraws method capability, the controller closes the affected listener before modifying its installed method policies. An unavailable capability used only by a new policy leaves the existing listener serving. It verifies the rules before reopening the listener. For rollback, withdraw the method-dependent routes and verify cleanup while the patched workers and controller flags are available.
