# HTTPRoute method matching on Amphora

The method profile matches the nine Gateway API v1.7.0 HTTP methods by their exact uppercase value. Within an alternative, the method is combined with the listener hostname, path and configured exact headers. Multiple alternatives can select the same backend. An unmatched request receives HTTP 404. A configured catch-all route can handle it instead.

1. Apply the Octavia migrations and update the API and Amphora workers to builds that support `HTTP_METHOD` and fixed HTTP responses. Enable `enabled_http_method_match_providers = amphora` and `enabled_gateway_action_providers = amphora` in Octavia's `[api_settings]` section. For matches that use exact headers too, enable `enabled_http_header_exact_providers = amphora`.
2. Read `GET /v2/lbaas/providers/amphora/gateway_capabilities` using the controller's project and regional endpoint. It must advertise `http_method_match_v1` and `fixed_http_responses_v1`. An exact-header match also requires `http_header_exact_v1`.
3. Enable `--octavia-http-method-match` and `--octavia-fixed-http-responses` on the controller. Add `--octavia-http-header-exact` for exact headers. The standalone overlay `config/octavia-http-method-match` and the Magnum overlay `integrations/magnum-capi-helm/workload-octavia-http-method-match` set all three flags. For Magnum, render the overlay as `gateway-controller.yaml` and pin the manifest checksum and controller image in the conductor configuration. [Magnum operator procedure](qualification/v1.7.0/magnum-operator.md)

Amphora evaluates redirects before forwarding. If an unrestricted redirect overlaps a higher-priority forwarding rule that adds a method predicate, the controller omits the affected redirect alternative and reports `Accepted=False` with reason `UnsupportedValue`. Redirects and forwarding rules can share a method when path guards preserve precedence, or use disjoint methods.

A temporary discovery failure keeps the last verified policies serving and pauses changes that would remove their protection. If Octavia explicitly withdraws method capability, the controller closes the affected listener before modifying its installed method policies. It verifies the rules before reopening the listener. For rollback, withdraw the method-dependent routes and verify cleanup while the patched workers and controller flags are available.
