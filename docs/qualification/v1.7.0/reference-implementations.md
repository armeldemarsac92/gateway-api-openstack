## Ownership across a cloud boundary

AWS adds a finalizer before deploying a Gateway model. During deletion it deploys the deletion model and releases shared security-group references before removing that finalizer. Its resource tags include a cluster, stack and logical resource identifier. The tracking tests inspect the exact sets of tags. The fork can use the same ordering to recover after an API timeout. Octavia additionally serializes child updates under its parent LB and exposes asynchronous provisioning states. Keep the Gateway UID lock, fresh ownership checks, parent/project validation and explicit child deletion in the existing writer. ELBv2 listener actions, ARN identity and target group bindings have different public APIs. ## Routing and status describe different observations

Envoy translates each route against a specific parent. Its HTTP compiler keeps explicit destination weights and can build local responses when references fail. A fixture contains three equal-weight destinations, including two invalid ones, and records reference status alongside the generated routing model. Route status updates merge a condition into a selected parent entry and carry its generation. Transfer the distinction between a reference error and the fraction of requests that still reach a good Service. The xDS representation can directly encode invalid destinations and responses. Stock Octavia needs a public provider operation with equivalent wire behavior before this fork can advertise that contract. ## Service-parent traffic

Istio resolves Service parents and produces mesh and Gateway route configurations independently when both are needed. Its route status can include waypoint-specific errors. The integration tests call workload B over HTTP and workload C over gRPC from workload A. Each checks the request header applied by its Service-parent route. Use that observable effect as the fork's east-west proof, and add controls for namespace enrollment and revocation. Istio achieves those results using its own traffic interception and configured proxies. Selecting a Kubernetes Service parent in an Octavia controller alone leaves the Service traffic path unchanged.
