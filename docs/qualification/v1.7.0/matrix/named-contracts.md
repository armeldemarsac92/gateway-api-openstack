# Named feature contract and implementation matrix

Each row maps one upstream `AllFeatures` entry to its API contract, its feature registry channel, profile support where relevant, concrete implementation action and a minimal behavioral oracle. **Standard and Experimental are release channels, not Core and Extended support levels.** The support column reflects profile classification or the contract scope stated; resource-level rows include several individual clauses with different support levels. Registry channel is the release channel of the named conformance feature. For exact schema availability, including filter enums and validation differences on shared objects, inspect [property paths](crd-channels.md) and [constraint diff](schema-constraints.md). A Standard feature can contain implementation-specific cases and a shared field can admit different enum values across channels.

Across recorded local runs, **122 of 170** registered cases have a PASS on Standard and **123 of 170** have a PASS on Experimental. **26 of 64** named features have at least one registered case and a PASS for every associated case on both channels.

The counts show cases with a PASS out of all associated cases for each channel. A case counts once per channel even if it passed in several modes, and it can contribute to several features. These runs use different controller revisions and configurations, including stock Octavia, opt-in Amphora capabilities, and Istio ambient. Status cases count for the assertions they make. A feature without a registered case needs separate behavioral evidence. Deployed Hibiscus qualification remains pending. Run `python3 docs/qualification/v1.7.0/matrix/feature-status.py` after changing the case ledger.
