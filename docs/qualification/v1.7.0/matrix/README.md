## Requirements not captured by distinct feature names

Core Gateway/HTTPRoute requirements include listener attachment and namespace authorization, hostname intersection and route precedence, exact and prefix path matching, weighted and invalid backends, conditions and status ownership, and rule-level request header modification. These are not optional simply because no separate feature name appears in the inventory. [HTTPRoute types](https://github.com/kubernetes-sigs/gateway-api/blob/e26d183dbbc1bb782b78addbd26faba03955c152/apis/v1/httproute_types.go) · [Gateway types](https://github.com/kubernetes-sigs/gateway-api/blob/e26d183dbbc1bb782b78addbd26faba03955c152/apis/v1/gateway_types.go) · [rule-level header test](https://github.com/kubernetes-sigs/gateway-api/blob/e26d183dbbc1bb782b78addbd26faba03955c152/conformance/tests/httproute-request-header-modifier.go).

The Standard schema contains route retry fields, while the retry features remain Extended. Experimental adds e.g. listener external authorization, HTTPRoute external authorization and session persistence, route default-gateway selection, and address routability. The full path diff is in the companion inventory; absent path differences do not rule out changed enums or validation. [HTTPRoute types](https://github.com/kubernetes-sigs/gateway-api/blob/e26d183dbbc1bb782b78addbd26faba03955c152/apis/v1/httproute_types.go).

`XBackend`, `XBackendTrafficPolicy`, `XMesh` and `XTelemetryPolicy` are Experimental-only CRDs. They respectively require backend abstraction and lifecycle, backend traffic policy translation, mesh data-plane/service attachment, and telemetry policy implementation. Their presence in the bundle does not itself establish profile conformance or a working Octavia mapping. The generated path inventory is not a complete assessment of their normative semantics, applicability or available tests. In particular, it does not substitute for an individual policy and provider design.

An Experimental HTTPRoute or GRPCRoute rule with one core Service can keep a session on the same endpoint. The operator enables the route setting and the regional header or cookie capability. The signed manager exercised HTTP headers and cookies, gRPC metadata, Service recreation and withdrawal of one rule’s affinity. The Standard schemas omit the inline field. A subsequent Experimental run exercised a 3:1 HTTPRoute and GRPCRoute with two Services and two endpoints per Service. Replaying a session preserved affinity within the selected Service and retained the weight of a cross-namespace backend through grant withdrawal and restoration. [Weighted session results](../provider/weighted-route-session-affinity/receipt.json) [Operator setup](../../../operator-octavia-backend-retry-budget.md#configure-session-persistence-on-a-route-rule) · [Both channel receipts](../provider/route-rule-session-persistence/receipt.json)

On one shared HTTP listener, each local channel withdrew a retiring HTTPRoute and its two Octavia matching rules. Its neighbor served 85 successful origin requests during removal. Kubernetes, the installed Octavia worker and native HAProxy participated. [Conditional removal and finalizer observations](../provider/conditional-l7-removal/receipt.json)
