# Magnum CAPI Helm: lifecycle evidence (2026-11-20)

## Boundary and versions

This is source and package evidence, not a deployed-inventory or runtime result. [Hibiscus release index](https://releases.openstack.org/hibiscus/) lists Magnum **23.0.0**, commit `1910928b7d9f788b8a959877efe3806e2c623e09`, as both first and latest Hibiscus release at inspection. The independent [Magnum release index](https://releases.openstack.org/teams/magnum.html) lists **magnum-capi-helm 1.4.0**, `a8b82c2480a286a10b60ecc1d94c6cd9f1d01823`, as latest 1.4 release. These are baselines, not evidence of what any deployment runs. Driver selection is request/template, image property, configured default, then registered-driver fallback; [validation](https://github.com/openstack/magnum/blob/1910928b7d9f788b8a959877efe3806e2c623e09/magnum/api/validation.py#L65) writes the resolved driver into the template. Inspect the real template, service packages and configuration before applying these findings.

## Real chart and render path

Driver [configuration](https://github.com/openstack/magnum-capi-helm/blob/a8b82c2480a286a10b60ecc1d94c6cd9f1d01823/magnum_capi_helm/conf.py#L31) defaults to management kubeconfig and namespace prefix `magnum`, repository `https://azimuth-cloud.github.io/capi-helm-charts`, chart `openstack-cluster`, version `0.10.1`; the repository/name/default are operator overrides. [Version selection](https://github.com/openstack/magnum-capi-helm/blob/a8b82c2480a286a10b60ecc1d94c6cd9f1d01823/magnum_capi_helm/driver.py#L550) reads `capi_helm_chart_version` from the cluster template only, not per-cluster labels; ordinary registered labels merge template then cluster overrides via [driver label logic](https://github.com/openstack/magnum-capi-helm/blob/a8b82c2480a286a10b60ecc1d94c6cd9f1d01823/magnum_capi_helm/driver.py#L503). Deep merge concatenates lists and treats `None` as retaining defaults ([helm.py](https://github.com/openstack/magnum-capi-helm/blob/a8b82c2480a286a10b60ecc1d94c6cd9f1d01823/magnum_capi_helm/helm.py#L32)); it is not a generic documented user-supplied values override.

Retrieved [actual index](https://azimuth-cloud.github.io/capi-helm-charts/index.yaml) and [packaged chart](https://azimuth-cloud.github.io/capi-helm-charts/openstack-cluster-0.10.1.tgz). Index records appVersion `856f8fb`, SHA-256 `fa3c30070e6f9f6684bfb10641917089b5d8453d91bc566230544029a0380d9d`; local archive hash matches. The index identifies chart source revision [856f8fb7372615ac0d3173d9b5d91fe605c9aeac](https://github.com/azimuth-cloud/capi-helm-charts/tree/856f8fb7372615ac0d3173d9b5d91fe605c9aeac). The parent chart vendors `cluster-addons` and defaults addons and OpenStack integrations enabled. The exact published package is authoritative for this check; appVersion is a short source revision, not proof of the deployed package or reproducible source tree.

[_update_helm_release](https://github.com/openstack/magnum-capi-helm/blob/a8b82c2480a286a10b60ecc1d94c6cd9f1d01823/magnum_capi_helm/driver.py#L1001) builds cluster-specific values including management Secret reference, API-server LB, networks, node groups and OCCM `cloudConfig.LoadBalancer`. It forces `addons.ingress.enabled=false` with a TODO about LB cleanup. [Helm client](https://github.com/openstack/magnum-capi-helm/blob/a8b82c2480a286a10b60ecc1d94c6cd9f1d01823/magnum_capi_helm/helm.py#L73) executes `helm upgrade --install` against the management cluster, history max 10, 5-minute timeout, no explicit atomic or wait flag; it does not establish workload controller readiness by itself.

The actual packaged `openstack-cluster/charts/cluster-addons/templates/custom-addons.yaml` supports `addons.custom` HelmRelease or Manifests with labeled management objects, workload target namespace and release name. `values.yaml` documents exact chart version and custom manifests. This is a chart extension seam, **not a currently exposed driver label or existing Gateway addon**: driver must deliberately construct and validate values, or an operator supply a separately maintained chart/repository. The template accepts arbitrary manifests and chart coordinates; do not expose unrestricted values to tenants. The packaged `templates/openstack/cloud-config.yaml` creates a management `Manifests` object whose template materializes workload `cloud-config` Secret using `cloud_identity.data`; actual propagation and refresh depend on the addon controller and must be proven. Workload namespace, credential projection and its consumers must be explicitly designed; a management Secret name is not by itself a workload Secret.

## Lifecycle and ownership

* [Create](https://github.com/openstack/magnum-capi-helm/blob/a8b82c2480a286a10b60ecc1d94c6cd9f1d01823/magnum_capi_helm/driver.py#L1238) generates persistent release name, creates management namespace, application credential and certificate Secrets, then Helm release. [App credential creation](https://github.com/openstack/magnum-capi-helm/blob/a8b82c2480a286a10b60ecc1d94c6cd9f1d01823/magnum_capi_helm/common/app_creds.py#L61) leaves role filtering as TODO. Project and least privilege are not demonstrated. Reusing this credential couples deletion and rotation to existing infrastructure; consider a dedicated scoped identity with a separately defined owner and cleanup policy.
* [Status](https://github.com/openstack/magnum-capi-helm/blob/a8b82c2480a286a10b60ecc1d94c6cd9f1d01823/magnum_capi_helm/driver.py#L286) requires CAPI conditions, nodegroup status and every returned labeled addon to have `Deployed`, and maps `Failed`/`Unknown` to failure. No explicit timeout is implemented ([status loop](https://github.com/openstack/magnum-capi-helm/blob/a8b82c2480a286a10b60ecc1d94c6cd9f1d01823/magnum_capi_helm/driver.py#L404)). Empty addon list can pass; deployed addon phase is not proof GatewayClass, Gateway, provider graph or traffic are healthy.
* [Rotation](https://github.com/openstack/magnum-capi-helm/blob/a8b82c2480a286a10b60ecc1d94c6cd9f1d01823/magnum_capi_helm/driver.py#L1360) applies a replacement management Secret before removing old app credential. On reported creation/apply errors it restores owner field, sets UPDATE_FAILED and raises; failure deleting old credential is reported in status_reason but operation completes. The check compares new ID with old, not evidence all workload consumers reloaded or that traffic survives. A partial failure after applying the new Secret also needs explicit reconciliation/recovery.
* [Upgrade](https://github.com/openstack/magnum-capi-helm/blob/a8b82c2480a286a10b60ecc1d94c6cd9f1d01823/magnum_capi_helm/driver.py#L1299) changes template and re-renders; viability validation is TODO. `rollback` parameters on update/upgrade are not used in the inspected path. Helm history is not an automatic verified rollback. Define version compatibility and recovery before upgrading shared CRDs or controller.
* [Delete](https://github.com/openstack/magnum-capi-helm/blob/a8b82c2480a286a10b60ecc1d94c6cd9f1d01823/magnum_capi_helm/driver.py#L1266) marks nodegroups deleting and uninstalls management release asynchronously; not-found uninstall is tolerated, other errors propagate ([helm client](https://github.com/openstack/magnum-capi-helm/blob/a8b82c2480a286a10b60ecc1d94c6cd9f1d01823/magnum_capi_helm/helm.py#L113)). Once CAPI Cluster disappears, [cleanup](https://github.com/openstack/magnum-capi-helm/blob/a8b82c2480a286a10b60ecc1d94c6cd9f1d01823/magnum_capi_helm/driver.py#L340) removes labeled management Secrets and credential; credential deletion errors become status_reason while status becomes DELETE_COMPLETE. No Gateway graph cleanup gate is established in this path. An addon must finalize Gateway resources while workload API, controller and credential remain available, confirm identity-scoped cloud absence, and only then uninstall/revoke. A bounded failure/retry and explicit operator orphan-recovery path is required if the workload API is lost; do not delete by broad project or generic LB description. Preserve API-server and OCCM Service LBs, other tenants, shared CRDs, GatewayClasses and admission resources owned elsewhere.

## Minimal acceptance and missing inputs

| Scenario | Status | Required proof / inputs |
|---|---|---|
| Inventory and opt-in | Unrun | Actual Magnum/driver/chart versions and digest, management/workload contexts, label permissions, explicit opt-in, namespace and unique cluster identity. |
| Install, isolated ownership | Unrun | Exact controller image digest, Gateway API bundle owner/version, class ownership, scoped credential and provider/network; two clusters and pre-existing API/Service LBs remain unaffected. |
| Status and traffic | Unrun | Addon phase plus current-generation class/Gateway/Route conditions; known backend HTTP response through owned VIP; failure visibly blocks completion. |
| Restart/rotation | Unrun | Replacement Secret reaches consumer, successful new auth before old revocation, restart without duplicate LB, continued traffic; failure and old-credential deletion recovery. |
| Upgrade/rollback | Unrun | Explicit compatibility and shared CRD owner; pinned pre/post versions, traffic and ownership, failed upgrade recovery without deleting existing graphs. |
| Disable/uninstall and delete | Unrun | Stop creation, finalize routes/Gateways while controller/credential alive, audit zero identity-owned cloud resources, retain other LBs and shared CRDs; retry and operator orphan recovery when API is unavailable. |

This source inspection verified the package digest and templates; no cloud calls, cloud credentials, tests against a cluster, provider traffic or deletion were performed. The fork’s [operator guide](magnum-operator.md) covers the opt-in patch, the real driver render check and the deployment steps. The published chart URL and archive checksum above identify the package used in this inspection.
