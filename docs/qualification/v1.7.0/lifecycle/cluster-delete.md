# Magnum cluster deletion on the local management plane

The stock Magnum 23 conductor and periodic job used the opt-in 1.4.0 driver patch, a disposable management API, a real parent Helm release and a local database. Without a recorded drain acknowledgement the conductor reported `DELETE_FAILED` and retained the enrolled resources. With a synthetic acknowledgement, the parent Helm release and its gateway manifests were removed. A still-finalizing CAPI Cluster held Magnum at `DELETE_IN_PROGRESS`. After the fixture allowed CAPI finalization, the next periodic poll recorded `DELETE_COMPLETE` and removed the cluster and nodegroup rows.

The control cluster and Helm release, the dedicated Gateway credential and nine shared CRD UIDs survived. The two operator enrollment records were removed separately after inspection. The Keystone adapter recorded the cluster credential deletion request. The CAPI finalizer, cloud discovery and drain acknowledgement were simulated. Actual server deletion, amphora and port cleanup, and the live IAM audit still require an operator cloud.
