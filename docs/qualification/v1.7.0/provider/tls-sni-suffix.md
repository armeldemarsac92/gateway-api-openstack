# TLSRoute wildcard SNI and ReferenceGrant changes

The same private VIP served three routes on one TLS passthrough listener. One route selected a Service for `*.example.test`, a second selected a Service in another namespace for `*.shop.example.test`, and a third selected its own Service for `vip.shop.example.test`. Both wildcard levels served names more than one label deep. The parent name `shop.example.test` reached the broader route.

| Channel | Successful TLS exchanges over the three grant states | Upstream HTTPS requests passed | Upstream nonmatching TLS connections rejected | Receipts |
|---|---:|---:|---:|---|
| Standard | 16 of 30 | 9 | 4 | [Grant and traffic](tls-sni-suffix-evidence/lifecycle-standard.json) · [Registered cases](tls-sni-suffix-evidence/upstream-standard.json) |
| Experimental | 16 of 30 | 9 | 4 | [Grant and traffic](tls-sni-suffix-evidence/lifecycle-experimental.json) · [Registered cases](tls-sni-suffix-evidence/upstream-experimental.json) |

With the grant present, six of ten fresh TLS connections reached their expected applications. On withdrawal the two names covered by the narrower route closed, the exact name continued to serve, and three names still reached the broader route. The narrower TLSRoute remained accepted with `ResolvedRefs=False/RefNotPermitted` and its managed `Programmed` condition became false. Re-creating the grant restored both names on the original route UID and generation. Unknown names and a connection without SNI stayed closed. Positive connections checked the certificate, the SNI seen at the backend and the echoed payload. Gateway removal cleared the managed route parents and the owned Octavia resources.

In a separate Standard run the project already used all three available pools. Octavia rejected an additional pool with HTTP 403. On grant withdrawal, the controller retained the narrower selector and emptied its verified backend pool. The broader and exact backends kept serving their own names. The fixture restored the prior project limit before re-creating the grant. A focused graph test also checks handoff between two route owners at quota. [Quota and traffic](tls-sni-suffix-evidence/quota-standard.json) · [Owner handoff test](../../../../internal/cloud/openstack/graph/tls_sni_graph_test.go)

The upstream cases `TLSRouteHostnameIntersection` and `TLSRouteMultipleRoutesAttachmentSameHostnameIntersection` both passed on both release channels with the original Gateway API v1.7.0 tests and manifests. The local fixture ran the Kubernetes API, the manager extracted from the release OCI archive, Octavia's API and Amphora renderer from the published wheel, HAProxy 3.0.19 and actual echo processes. It supplied Keystone, Neutron and worker completion locally. The Kubernetes API server had no kubelet. The upstream echo processes used v0.2.0 while the base workload declares v0.1.0. The regional Magnum and Amphora fleet runs remain open.
