# Three Core HTTPRoute cases on stock Octavia 19

The stock controller from `e17cf858d11d04cf35d298ad19d9498ccde6b491` rejected each of these Routes on both v1.7.0 channels. Each native case obtained a Gateway address, then failed its original wait for the Route parent to become `Accepted=True`. The controller reported `Accepted=False/UnsupportedValue`. The native HTTP assertions follow that wait and were never reached.

| Registered case | Controller diagnostic | Additional requests through the Gateway, per channel | Native results |
| --- | --- | --- | --- |
| HTTPRouteHeaderMatching | Header, query parameter and method matches are unsupported. | Three requests received HTTP 503. | [Standard](stock-core-http-cases/matching-standard.json) · [Experimental](stock-core-http-cases/matching-experimental.json) |
| HTTPRouteRequestHeaderModifier | Octavia needs route-scoped request header operations. | Five requests received HTTP 503 across the set, add, remove, combined and case-insensitivity paths. | [Standard](stock-core-http-cases/modifier-standard.json) · [Experimental](stock-core-http-cases/modifier-experimental.json) |
| HTTPRouteWeight | The stock rule accepts exactly one backend reference. | Ten requests received HTTP 503. The upstream 70/30/0 statistical phase never started. | [Standard](stock-core-http-cases/weight-standard.json) · [Experimental](stock-core-http-cases/weight-experimental.json) |

Each run used its own Kubernetes 1.36.2 API server, genuine release CRDs, the tagged upstream case and manifests, an unpatched Octavia 19.0.0 WSGI API, its Amphora renderer and a real HAProxy 3.0.19 process. The fixture supplied project identity, Neutron discovery, worker completion and the agent transport on an isolated loopback network. The header cases directly reached all five pinned echo replicas before applying the Route. The four header receipts record zero attached Routes on the HTTP listener. All six receipts record zero L7 policies and zero pools. [Header matching case](https://github.com/kubernetes-sigs/gateway-api/blob/e26d183dbbc1bb782b78addbd26faba03955c152/conformance/tests/httproute-header-matching.go) · [Header modifier case](https://github.com/kubernetes-sigs/gateway-api/blob/e26d183dbbc1bb782b78addbd26faba03955c152/conformance/tests/httproute-request-header-modifier.go) · [Weight case](https://github.com/kubernetes-sigs/gateway-api/blob/e26d183dbbc1bb782b78addbd26faba03955c152/conformance/tests/httproute-weight.go)

The stock provider probe explains the exact-match gap. Its `HEADER/EQUAL_TO` rule matched the single incoming field `Version: one, other` against the configured value `one`. A separate API probe observed the rejection of a per-route request-header operation. These checks and all six receipts are local qualification. The seven profiles on both live Hibiscus channels remain unrun.
