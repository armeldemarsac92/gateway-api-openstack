# HTTP response headers on an Amphora listener

An operator can enable `ResponseHeaderModifier` to set, append or remove headers on the response from an individual HTTPRoute rule. Enable the controller flag `--octavia-response-header-modifier` and use an Amphora region advertising `response_header_operations_v1`. For rules modifying both request and response headers, enable both capabilities. | `HTTPRouteResponseHeaderModifier` | 8 of 8 passed | 8 of 8 passed |

The eight subtests sent requests through Amphora-rendered HAProxy to real upstream echo Pods in a disposable Kind cluster for each channel. They cover a header set on the response, appended values on an existing header, removal, multiple operations, case-insensitive names and request and response modifications on one rule. The parent reported `Accepted=True` and `ResolvedRefs=True`. At the final status snapshot the controller-specific `Programmed` condition was still `False/Pending`. The case exercised live traffic. Keystone, network provisioning and cloud worker completion used local fixtures. [Original test](https://github.com/kubernetes-sigs/gateway-api/blob/e26d183dbbc1bb782b78addbd26faba03955c152/conformance/tests/httproute-response-header-modifier.go) · [Two-channel receipts](response-header-modifier-results.json) · [Replay and upstream reports](https://github.com/armeldemarsac92/gateway-api-openstack/releases/download/hibiscus-dev-6e41a107c7ce7ce2a25782386aba9f8ec542faa5/hibiscus-response-header-case.tar.gz)

The provider tests exercised two policies sharing a pool, a fixed-error response and clearing a policy's operations. The controller refuses to program response operations in regions missing the capability. The provider also checks active policies when enabling a listener or a load balancer after a regional opt-out.
