# HTTPRoute selects Pods with an Experimental XBackend

A tenant can point an HTTPRoute at an XBackend in the same namespace. In the Endpoint member mode, the controller adds ready, nonterminating Pods that match every label to an Octavia pool. Each member uses the port declared by the XBackend. The operator installs the v1.7.0 Experimental CRDs and workload overlay, and provides a network path from Amphora to the Pod IPv4 addresses. The local replay applied the published Experimental bundle and ran the extracted controller with its rendered service-account role. It created a same-named Service and a ready, matching Pod in a different namespace. Both remained present through the selector change and detachment. A direct request identified each of the three live peer processes. The same manager and role came from source `f150a6e006d027106da2aaed6b82cb262bcf1b1a`. The provider used the stock Octavia 19.0.0 API with SQLite, octavia-lib 3.12.0, the Amphora renderer and HAProxy 3.0.19. The Kubernetes 1.36.2 envtest API server has no kubelet. The fixture supplied Pod addresses and readiness after checking the HTTP peers. Keystone, Neutron metadata and provisioning completion were local fixtures. The earlier controller at `bebbb4304` reported `ResolvedRefs=False/InvalidKind` and produced three HTTP 503 responses with zero additional Octavia writes. The upstream v1.7.0 suite contains no registered XBackend case. This replay exercised default HTTP on an IPv4 Endpoint-mode Gateway. Host-network Pods are excluded. The controller supports HTTP, HTTP/1.1 and the separate opt-in h2c capability. A separate local Gateway trial covered ExternalHostname rotation and withdrawal. A ServerOnly Gateway trial verified the selected Pod's TLS identity, closed its traffic when the CA was withdrawn and recovered after restoration. [Conditions and HTTP responses](xbackend-server-tls-evidence/receipt.json) An opt-in session cookie kept the selected Pod across two paths, then switched to the remaining ready Pod. [Cookie requests and membership](xbackend-session-cookie-evidence/receipt.json) With an operator-enrolled client certificate, an EndpointSelector origin accepted the certificate presented by Amphora. Withdrawing its cross-namespace Secret grant disabled the pool and cleared its client identity. After restoration the Pod saw certificate A again, then certificate B after rotation. [Client certificate traffic and conditions](xbackend-client-tls-evidence/receipt.json) An optional absolute timeout limits affinity across HTTPRoutes that share the same XBackend. [Timed cookie traffic](xbackend-cookie-deadline-evidence/receipt.json) A permanent cookie can stay in the client jar across sessions. A cookie scoped to `/reports` kept the client on the same Pod for that path and its descendants. Header persistence, additional route kinds and a deployed Hibiscus run remain open.
