# Terminate TLS for a TCP Service

A Gateway listener with `protocol: TLS` and `tls.mode: Terminate` can accept client TLS for an application that speaks plaintext TCP. An attached TLSRoute selects the Service using its own hostname or the listener hostname. The listener requires an operator-enrolled certificate. A TLSRoute using passthrough on a separate Gateway can still deliver the original TLS session to its Service. [Certificate enrollment](../../../operator-https.md) · [Passthrough](tlsroute-sni.md)

## Enable in an Amphora region

Use Octavia `19.0.1.dev13` and octavia-lib `3.12.1.dev6`, including the corresponding database migration, worker and Amphora driver. In Octavia’s `[api_settings]`, enable `allow_tls_terminated_listeners` and include `amphora` in `enabled_tcp_tls_termination_providers`. Read the regional provider capability endpoint and check for `tcp_tls_termination_v1`. The database revision for this change is `b681388ab702`. [Octavia change](https://github.com/armeldemarsac92/octavia/pull/10) · [octavia-lib change](https://github.com/armeldemarsac92/octavia-lib/pull/6)

Set `spec.memberMode: Endpoint` on the `OpenStackGatewayClassConfig`. Select IPv4 VIP and member subnets, configure Amphora to reach the Pod endpoints and check the return path from the Pods. [Direct endpoint network requirements](../../../reference/class-configuration.md#direct-endpoint-members)

Use the controller’s `--octavia-tcp-tls-termination` option. The standalone and Magnum workload overlays include the operator certificate map. Enroll the exact Secret UID and resourceVersion with the existing certificate helper. Grant the Gateway access when the certificate Secret belongs to another namespace. Give the listener its own port and configure the backing Service to accept plaintext TCP if no BackendTLSPolicy applies. Both overlays can read BackendTLSPolicy so a Service port that still requires authentication stays closed when backend TLS origination is disabled. [Standalone overlay](../../../../config/octavia-tcp-tls-termination/kustomization.yaml) · [Magnum workload overlay](../../../../integrations/magnum-capi-helm/workload-octavia-tcp-tls-termination/kustomization.yaml) · [Enrollment procedure](../../../operator-https.md)

Amphora exposes a TCP listener with `tcp_tls_termination=true`. SNI rules select the TCP backend pool. A Service without a backend TLS policy receives plaintext TCP. An unknown name on a named listener closes the connection. Removing a required grant or certificate enrollment withdraws forwarding. For rollback, drain the listener, remove its Gateway and verify cleanup in Octavia while the enrolled controller is still running.

A listener and route that both omit hostnames still need qualification. Combining termination and passthrough on one port reports `ProtocolConflict` in this configuration. [Feature matrix](../matrix/named-contracts.md)

## Authenticate the TCP backend

A terminating TLSRoute can open a new TLS connection to its Service under a BackendTLSPolicy. Set both `--octavia-tcp-tls-termination` and `--octavia-backend-tls-policy` on the controller and select Octavia microversion 2.8 or later. Use the operator certificate mapping for the listener and a local ConfigMap CA with a fixed DNS validation hostname for the Service. The CA used for the backend must be available in the regional Barbican service. [Backend policy configuration](../../../operator-octavia-backend-tls-policy.md)

On Amphora, enable `tcp_tls_termination_v1`, `backend_tls_hostname_v1` and `tcp_tls_backend_auth_v1` in the region and verify the provider capability response. The last capability requires HAProxy support for strict backend hostname verification. The public pool reports `tls_enabled`, `backend_tls_hostname` and its CA reference. A requested Gateway client identity for the backend falls outside this TCP profile. [Octavia packages and regional configuration](https://github.com/armeldemarsac92/octavia/releases/tag/hibiscus-tcp-backend-tls-41dbfea19753)

The original Gateway API v1.7.0 case `BackendTLSPolicyTLSRouteTerminate` passed on Standard and Experimental. The TLS client negotiated TLS 1.3 for `tls.example.com` on port 8443. The echo Pod replied `PONG` and reported TLS with backend SNI `abc.example.com`. The policy’s Gateway ancestor reported `Accepted=True` and `ResolvedRefs=True` at the current generation. Kubernetes, the echo Pods, Octavia and Barbican REST, and HAProxy ran locally. Identity, Neutron allocation and the Amphora and worker transports were simulated. Qualification on a deployed Hibiscus cloud is pending. ## Share a port between termination and passthrough

Choose the mixed-mode controller overlay to expose a terminating TLS listener and a passthrough TLS listener on the same address and port. The terminating sections on that port must use the same operator-enrolled certificate. Passthrough preserves the certificate and TLS session of the destination Service. Configure a distinct hostname on each section and target that section from its TLSRoute. [Standalone overlay](../../../../config/octavia-tcp-tls-mixed-mode/kustomization.yaml) · [Magnum workload overlay](../../../../integrations/magnum-capi-helm/workload-octavia-tcp-tls-mixed-mode/kustomization.yaml)

Upgrade the regional database, API, workers, Amphora fleet and driver library. In Octavia, add `amphora` to `[api_settings] enabled_tcp_tls_mixed_mode_providers` and enable the existing TCP termination and SNI passthrough capabilities. Verify that the regional capability endpoint lists `tcp_tls_mixed_mode_v1`, `tcp_tls_termination_v1` and `tls_sni_passthrough_v1`. The shared TCP listener has no default pool. Its SNI policies select the transport mode separately for each pool. This profile uses opt-in Amphora extensions. [Octavia packages](https://github.com/armeldemarsac92/octavia/releases/tag/hibiscus-mixed-tls-ffeed635ef22) · [Driver library packages](https://github.com/armeldemarsac92/octavia-lib/releases/tag/hibiscus-mixed-tls-4fe5ac72a508)

On Standard and Experimental, the original `TLSRouteMixedTerminationSameNamespace` case passed on port 8883. Connections to `tls.example.com` negotiated the enrolled certificate and the echo Pod received plaintext on port 3000. Connections to `abc.example.com` negotiated the backend certificate and the Pod received TLS with that SNI on port 8443. In a separate check on each channel, withdrawing each route closed its name while the other still returned `PONG`. Both names returned `PONG` after each restoration. The tests ran on local Kind with simulated OpenStack infrastructure dependencies. Deployed Hibiscus qualification remains pending.
