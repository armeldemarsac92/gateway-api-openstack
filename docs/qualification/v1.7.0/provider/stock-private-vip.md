# Requesting a private IPv4 VIP from Octavia

Stock Amphora accepts a requested address when it creates a load balancer on the operator-selected VIP subnet. In the Octavia 19.0.0 WSGI fixture, both an exact IPv4 request and a subnet-only request returned HTTP 201. The Neutron driver sent the SDK a single fixed IP entry with the requested address in the first case and only the subnet in the second. The public GET returned the allocated VIP and its port in both cases. [Octavia create API](https://docs.openstack.org/api-ref/load-balancer/v2/#create-load-balancer) · [Hibiscus Neutron driver](https://github.com/openstack/octavia/blob/93689cb7701da65b5aad387bb824c477c64b0f2b/octavia/network/drivers/neutron/allowed_address_pairs.py)

A duplicate request produced a public 409 when the SDK parsed the synthetic Neutron IP allocation conflict. The original load balancer, VIP and port remained present and the contender had no database row or port. A PUT to change the VIP returned 400. Octavia's update type excludes the VIP address. Both fixture load balancers returned 404 after deletion. The probe uses real API validation, SQLite persistence, the Amphora provider and the Neutron driver, with synthetic Neutron IPAM and simulated worker completion. The pinned run used openstacksdk 4.20.0 and SQLAlchemy 2.0.52. [Octavia request types](https://github.com/openstack/octavia/blob/93689cb7701da65b5aad387bb824c477c64b0f2b/octavia/api/v2/types/load_balancer.py) · [Probe, results and reproduction](https://github.com/armeldemarsac92/gateway-api-openstack/releases/download/hibiscus-dev-719490a9b1fa73b0d80a0c5512c2c8107b16a235/hibiscus-provider-probes-719490a9b1fa.tar.gz)

Eight unmodified Neutron 29.0.0 tests also passed using its in-memory SQLite database. A separate run through its public port API returned 409 for an already allocated IPv4 and 400 for the network, broadcast and outside-subnet addresses. Replaying those actual error bodies through the SDK and the stock Octavia 19.0.0 Amphora provider returned 409 for the duplicate and a generic 500 for each invalid address. The controller checks usable IPv4 boundaries before allocating. These two API fixtures used separate databases. A deployed cloud remains necessary for end-to-end IPAM and traffic evidence.
