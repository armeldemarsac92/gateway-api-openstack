# HTTP listener and route hostnames on Hibiscus

HTTP hostname routing follows the [Hibiscus design](../superpowers/specs/2026-11-20-hibiscus-design.md) and [implementation plan](../superpowers/plans/2026-11-20-hibiscus.md). When routes have identical listener intersections, their original matching hostnames determine precedence before the paths are compared.

Gateway API v1.7.0 requires the implementation to ignore the port in the HTTP Host header for matching and to forward the original header. Its hostname intersection test sends both a bare hostname and one with an explicit port. [HTTPRoute API](https://github.com/kubernetes-sigs/gateway-api/blob/e26d183dbbc1bb782b78addbd26faba03955c152/apis/v1/httproute_types.go#L59-L68) · [Hostname intersection test](https://github.com/kubernetes-sigs/gateway-api/blob/e26d183dbbc1bb782b78addbd26faba03955c152/conformance/tests/httproute-hostname-intersection.go#L67-L98)

The listener may specify one exact DNS name or a leading wildcard. An HTTPRoute can declare multiple names. The controller creates a policy branch for each distinct hostname pattern and path match that survives intersection with the listener. For example, a listener for `api.example.com` and a route declaring `*.example.com`, `api.example.com` and `ignored.example.net` match requests to `api.example.com`. The exact route declaration determines precedence over a wildcard-only sibling. [Multiple-hostname qualification and rollback](../qualification/v1.7.0/provider/http-host-intersection.md) An omitted name takes the other side’s constraint. If both names are absent, the policy matches the path alone. A listener for `*.example.com` and a route for `*.shop.example.com` admit `a.shop.example.com` and `a.b.shop.example.com`. The apex `shop.example.com` falls outside that intersection. Disjoint names give the route `Accepted=False` with reason `NoMatchingListenerHostname`. [v1.7.0 hostname contract](https://github.com/kubernetes-sigs/gateway-api/blob/e26d183dbbc1bb782b78addbd26faba03955c152/apis/v1/httproute_types.go#L56-L108)

The controller writes the effective hostname as an anchored `HOST_NAME` regular expression using the public Octavia API. Octavia validates and escapes the expression and supplies HAProxy’s case-insensitive flag. The same policy also requires the path rule. [Octavia validation](https://github.com/openstack/octavia/blob/93689cb7701da65b5aad387bb824c477c64b0f2b/octavia/common/validate.py#L165-L177) · [Rule escaping](https://github.com/openstack/octavia/blob/93689cb7701da65b5aad387bb824c477c64b0f2b/octavia/common/jinja/haproxy/combined_listeners/jinja_cfg.py#L610-L635) · [Amphora renderer](https://github.com/openstack/octavia/blob/93689cb7701da65b5aad387bb824c477c64b0f2b/octavia/common/jinja/haproxy/combined_listeners/templates/macros.j2#L85-L113)

Stock Octavia counts the anchors, escaped separators and port expression against its 255-character L7 rule value limit. The controller rejects a hostname whose effective expression exceeds that limit with `Accepted=False`, reason `UnsupportedValue`, before cloud programming. For an existing route, the graph disables the affected policies, updates the owned `HOST_NAME` rule in place, and re-enables the policies after the new rule is observed. Routing through those policies pauses during that reconciliation. [Octavia rule API types](https://github.com/openstack/octavia/blob/93689cb7701da65b5aad387bb824c477c64b0f2b/octavia/api/v2/types/l7rule.py#L57-L97)

Enable `--octavia-long-http-hostnames` after the regional Amphora provider advertises `http_long_hostname_v1` through its authenticated Gateway capabilities endpoint. This allows up to 512 characters per `HOST_NAME` regular expression, including the escaping needed by valid 253-character exact and wildcard DNS names. A host exclusion uses the same expression with Octavia's inversion flag. Hosts are matched case-insensitively with the same optional numeric port, and the original Host reaches the backend.

If the controller cannot verify the capability, it closes the affected listener and waits for confirmed readback before changing its policies. A failed close is retried until Octavia reports the listener as active and administratively down. Policy and backend-target withdrawal remain available on the closed listener. Removing the opt-in preserves the binding and unrelated ports on an existing Gateway. The affected listener can reopen once the capability has been verified or its remaining hostname rules and sections fit the stock limit.

## Local evidence

With the regional option enabled, local Standard and Experimental runs each served a 253-character exact hostname, including uppercase and port-bearing requests, and a wildcard across one and two subdomain labels. The wildcard apex and a neighboring exact name made zero calls to the backend. [Both channel receipts](../qualification/v1.7.0/provider/long-http-hostnames/README.md)

The graph tests inspect the outgoing rule on creation and on upgrade from `EQUAL_TO`, including the action order and the exact path rule. Local HTTP/1.1 requests through the stock Octavia 19.0.0 policy macro and HAProxy 3.0.19 reached an echo backend with the original mixed-case Host and numeric port. The wildcard accepted nested subdomains and excluded the apex. The multi-listener hostname conformance case also passed all 33 request assertions on each channel in a local kind run. Strict rejection of malformed authorities and traffic on a deployed Amphora remain open. [Multi-listener results](../qualification/v1.7.0/provider/listener-hostname-runs/README.md) [Controller tests](../../internal/controller/httproute/httproute_logical_model_test.go)

During bundle version skew, an already-programmed exact route keeps forwarding when its hostname still fits the listener wildcard. A narrower listener restriction that the controller cannot prove triggers detachment. During an ordinary listener edit, the controller can complete a legacy binding's missing project annotation when the stored identity and both finalizers establish ownership. The Gateway and route can then finish programming the new hostname. [CRD skew cases](../../internal/controller/httproute/gateway_api_version_test.go) · [Legacy binding case](../../internal/controller/httproute/httproute_binding_checkpoint_test.go)

The routed HTTP listener requires an empty default-pool reference. On observing drift to a proven owned route pool, the writer closes the serving listener, clears the reference and waits for the change to settle before restoring service. The route pool and its members stay intact. An unproven pool raises an ownership conflict and stops cloud writes. [Adapter recovery and cleanup case](../../internal/cloud/openstack/graph/hibiscus_contract_test.go)
