# Exact HTTPRoute hostnames on Hibiscus

This is a stock routing increment of the [Hibiscus design](../superpowers/specs/2026-11-20-hibiscus-design.md) and [implementation plan](../superpowers/plans/2026-11-20-hibiscus.md). It applies to the existing single HTTPRoute and HTTP listener on Amphora.

Gateway API v1.7.0 requires the implementation to ignore the port in the HTTP Host header for matching and to forward the original header. Its hostname intersection test sends both a bare hostname and one with an explicit port. [HTTPRoute API](https://github.com/kubernetes-sigs/gateway-api/blob/e26d183dbbc1bb782b78addbd26faba03955c152/apis/v1/httproute_types.go#L59-L68) · [Hostname intersection test](https://github.com/kubernetes-sigs/gateway-api/blob/e26d183dbbc1bb782b78addbd26faba03955c152/conformance/tests/httproute-hostname-intersection.go#L67-L98)

The controller writes a public Octavia L7 rule with type `HOST_NAME`, comparison `REGEX` and an anchored value such as `^api\.example\.com(:[0-9]+)?$`. Octavia validates the regular expression, escapes the backslashes for the rendered configuration, and supplies HAProxy’s case-insensitive flag. The same L7 policy also requires the path rule. Routes without a hostname continue to use only the path rule. [Octavia validation](https://github.com/openstack/octavia/blob/93689cb7701da65b5aad387bb824c477c64b0f2b/octavia/common/validate.py#L165-L177) · [Rule escaping](https://github.com/openstack/octavia/blob/93689cb7701da65b5aad387bb824c477c64b0f2b/octavia/common/jinja/haproxy/combined_listeners/jinja_cfg.py#L610-L635) · [Amphora renderer](https://github.com/openstack/octavia/blob/93689cb7701da65b5aad387bb824c477c64b0f2b/octavia/common/jinja/haproxy/combined_listeners/templates/macros.j2#L85-L113)

Octavia counts the anchors, escaped separators and port expression against its 255-character L7 rule value limit. The controller rejects an unrepresentable hostname with `Accepted=False`, reason `UnsupportedValue`, before cloud programming. For an existing route, the graph disables the affected policies, updates the owned `HOST_NAME` rule in place, and re-enables the policies after the new rule is observed. Routing through those policies pauses during that reconciliation. [Octavia rule API types](https://github.com/openstack/octavia/blob/93689cb7701da65b5aad387bb824c477c64b0f2b/octavia/api/v2/types/l7rule.py#L57-L97)

## Local evidence

The graph tests inspect the outgoing rule on creation and on upgrade from `EQUAL_TO`, including the action order and the exact path rule. A local HTTP/1.1 check used the pinned Octavia 19.0.0 L7 policy macro and escaping function with standalone HAProxy 3.0.19 and an echo backend. Both rules forwarded the bare name in mixed case. The regex also forwarded `API.Example.COM:1234`, and the backend received the original header. A different domain, a longer domain, a hostname with a substituted dot, and an incorrect path did not reach that backend. On that fixture, unmatched requests returned HAProxy 503. The standalone check also identified a limitation in stock handling of malformed Host values. Strict rejection of invalid HTTP authorities remains an open provider requirement. This evidence covers the supported one-route configuration and valid Host values. Qualification on deployed Amphora and the full hostname intersection conformance case remain open.
