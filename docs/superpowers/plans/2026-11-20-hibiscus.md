# Hibiscus integration implementation plan

**Goal.** Deliver v1.7.0 behavior for every release-defined feature, with independently reproducible evidence for each channel and profile.

**Architecture.** A portable Gateway controller reconciles a complete Gateway graph through the public cloud APIs. The Magnum driver owns an opt-in workload installation. The provider extension and Service mesh are studies pending a separate implementation decision. [Approved design](../specs/2026-11-20-hibiscus-design.md)

**Tools.** Go 1.27.4, controller-runtime envtest, genuine Gateway API v1.7.0 CRDs and suite, stock Hibiscus source, magnum-capi-helm 1.4.0 and its selected chart.

## Local delivery

- [ ] Catalogue the tagged types, both CRD schemas, feature/profile registries and conformance cases in `docs/qualification/v1.7.0/`. Give unflagged semantics explicit behavioral checks. Pin ownership, routing, mesh and provider references. Distinguish code, simulated requests and operator observations.
- [x] Port `go.mod`, `go.sum`, `Dockerfile`, Makefile, CI, `test/design/core-mapping.json`, E2E evidence and active installation instructions together. Use the upstream registry delta to demonstrate the old mapping fails. Check the controller build, exact dependency, full unit suite, pinned linter, genuine envtest and image reproducibility.
- [x] Tighten `internal/controller/gateway_api_version.go` at the existing provisioning fence. Test a genuine bundle for each selected channel, same-release mixed CRDs, version mismatch and cleanup of an existing binding. Verify admission resources against each published manifest. Standard stays the default.
- [x] Exercise `internal/cloud/openstack/graph` through the normal provider entry point and its existing HTTP test transport. Simulate a lost mutation response and a fresh provider instance. Assert rediscovery and explicit deletion, and check protected API-server and OCCM load balancers survive. Keep the fake limited to the requests the scenario makes.
- [ ] Add stock profile behavior in traffic-sized increments. Work through Gateway attachment/status, authorized references and their revocation, protocol listeners, deterministic matching, policy resolution, and partial cloud failure. Write the failing behavioral check before each change. Record the exact provider limitation wherever an increment requires a decision.
- [ ] Support distinct UDP ports on one Gateway using the existing UID-keyed writer. Start with the two failing upstream cases. - [ ] Integrate the opt-in into the real magnum-capi-helm driver value builder and its management addon. Exercise the selected chart with the flag disabled and enabled. Verify credential replacement, certificate replacement, rollback, teardown ordering and identity-scoped recovery, first locally, then on the nominated environment.

## Qualification and decisions

- [ ] For predicates, headers, fixed/error responses, backend weights, gRPC and TLS SNI, give minimal public-API cases and pin the missing primitives. Specify negotiation and a provider-compatible public extension. For mesh, specify enrollment, parent/status ownership and normal client-to-Service routing. Submit each concrete architecture change for approval before implementing it.
- [ ] In a designated Hibiscus environment record versions, exact image digest and tagged cloud inventory. Send traffic through the private VIP to a known NodePort backend, restart and repeat, then remove the test graph and check the two control LBs. Exercise both credential and certificate rotation, upgrade, rollback, uninstall and cluster teardown.
- [ ] Run the unmodified v1.7.0 suite for all seven profiles and applicable Extended features on their respective clean channels. Exercise uncovered normative contracts separately. Publish per-mode evidence, environment and runbook with individual pass/fail/skip/unrun results. The real-cluster stages await an authorized target.

Each change has a focused regression or behavioral check, its operator impact and an atomic commit. Integrate disjoint work, review the combined changes independently, and rerun the checks affected by repairs.
